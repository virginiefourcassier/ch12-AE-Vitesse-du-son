# Plan proposé — garder Éléa et GitHub pédagogiquement synchronisés

1. **Histoire et contextualisation** : conserver les documents du parcours Éléa ; rétablir les illustrations correspondantes côté GitHub. Les SCORM/Genially d’origine restent fonctionnels dans Éléa ; leur équivalence GitHub reste à finaliser.
2. **Coup de tonnerre** : le laisser avant l’expérience des microphones dans les deux parcours. Rien à supprimer dans Éléa.
3. **Documents et acquisition** : placer les explications sur la date, la durée et l’usage du réticule avant la mesure autonome. Le cas échéant, déplacer dans Éléa l’activité de tutoriel correspondante, mais seulement après comparaison sur écran.
4. **Enregistrements LatisPro** : fournir les mêmes enregistrements expérimentaux aux deux groupes ; côté GitHub, les fichiers .ltp sont convertis en JSON utilisable sans logiciel.
5. **Questionnaire REAliser** : garder le quiz dans Éléa ; côté GitHub, la banque de questions numériques Moodle est récupérée mais les tirages et contraintes exacts restent à comparer.
6. **Collecte de mesures** : conserver la base Moodle pour le groupe Éléa ; préparer un formulaire distinct pour le groupe GitHub. Les deux travaillent sur la même expérience au bureau, sans mélanger leurs dépôts.
7. **Statistiques** : une synthèse adaptée à chaque groupe, avec les mêmes définitions de moyenne, écart-type expérimental et incertitude-type.
8. **Recherche d’une distance inconnue** : déplacer éventuellement cette activité après l’étude statistique dans Éléa et GitHub. Ne pas exploiter en tant que « nouvelle acquisition » le fichier inconnu identique au 70 cm.
9. **Devoirs et achèvement** : conserver Éléa comme outil de remise et d’évaluation de ses utilisateurs ; le groupe GitHub utilise une transmission séparée des scores, à sécuriser avant activation.

**À modifier dans Éléa, instruction par instruction uniquement lorsque la progression exacte aura été validée sur captures.**
